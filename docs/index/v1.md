# Stress index v1: draft, not published

This draft is not ready for forecasts or publication. The architecture requires tests on the 2019–2026 history and a backtest table before publication. Several calculation choices remain unspecified. The implementation raises `DefinitionGap` for fresh inputs rather than returning a claim. Stale load and weather return `stale_load` and `stale_weather` respectively. If both are stale, load is reported first.

## Model and source

The source for the following settings is the [S3–S7 architecture, stress index table](../architecture-s3-s7.md#stress-index-v1). The [plan](../../PLAN.md) adopts the architecture and requires a versioned definition and frozen hash. The draft TOML records these pinned settings; its SHA-256 covers the exact bytes passed to the parser.

| Element | Specified rule |
| --- | --- |
| Geography | PJM-wide demand; BWI weather. Forecast point NWS LWX/107,85; observed station NCEI USW00093721. |
| Alignment | Target local date D uses the high for D and the low of the night beginning D-1, mapped to its morning end date D. History uses calendar-day TMAX(D) and TMIN(D). This is an approximation of the morning low, not a claim about when TMIN occurred. |
| History | Complete days in the same calendar window, ±21 days, over the last three complete years and the current year. A forecast may use only information available at issue time. |
| Day type | Weekday or weekend; no holiday adjustment. |
| Peak | Least squares on same-day-type days: intercept plus `max(0, high - 65)` and `max(0, 50 - morning_low)`. Drop each hinge with fewer than ten nonzero days. |
| Level | Compare predicted MW to observed-peak p75, p90 and p97 in the window across both day types. Thresholds are inclusive for watch, strained and severe; below watch is calm, as named in the architecture Types table. |
| Hour | Mode of the peak hour among ten nearest same-day-type weather analogs. A mode tie goes to the earlier hour. |
| Alerts | Per-day annotations only. They do not change the level. |
| Scoring | A stress day is strained or severe; an hour hit is within one hour. Settlement is two days, provisional. |

The mart's complete-day, peak and temperature fields are described in [mart_day_history.sql](../../dbt/models/marts/mart_day_history.sql). Observed calendar-day temperatures are not historical NWS forecasts. Any backtest using them is an observed-weather hindcast, not validation of issued forecasts.

## Choices still needed

- Percentile interpolation and behavior on too few observations.
- Analog distance metric, scaling, and selection when distances tie at the tenth place; behavior with fewer than ten eligible days.
- Singular or ill-conditioned regression policy and minimum fitting sample.
- Exact calendar-window handling across year boundaries and leap days, and treatment of missing temperatures by each stage.
- Availability and revision cutoffs for historical observations, including how to demonstrate no lookahead at each issue time.
- NWS alert effective, onset, expires and ends precedence, and how active intervals map to local-date boundaries.

The existing implementation filters complete, prior dates by calendar window and day type where the window does not touch a year or leap-day boundary. This date filter alone cannot prove issue-time availability or revision cutoffs. It calculates the specified hinge retention, least-squares normal equations, inclusive level comparisons and the peak-hour mode tie. Alerts are supplied as date-keyed annotations; mapping NWS active intervals to dates is not implemented here. It raises on a singular fit and does not invent a fallback. It does not turn these pieces into a claim while the remaining choices are open.

A performance table requires settled calculation rules, issue-time cutoffs, exclusions, sample counts, errors, and stress-day outcomes. v1 remains draft and unpublished.

The remaining rules block these steps:

- Percentile interpolation blocks p75, p90, p97 thresholds, stress levels, and stress-day precision and recall.
- Analog distance, scaling, and selection ties block the ten-day analog set, peak-hour forecasts, and hour-hit rate.
- Sample requirements block eligibility for fitting, thresholds, and analogs, especially early-history dates.
- Singular or ill-conditioned fitting policy blocks regression handling and peak-MW error metrics.
- Calendar-boundary and missing-temperature handling block seasonal selection, leap-day handling, and defensible exclusions. Calendar-day temperature alignment is settled.
- Historical availability and revision cutoffs block issue-time input reconstruction and proof of no lookahead. Observed temperatures are not archived NWS forecasts.
- NWS alert-interval-to-date mapping blocks annotation validation only. It does not block numerical stress levels because alerts are annotation-only.

## Code shape

Two designs were considered. A combined `stress` module could own types and computation, with one import for callers. Separate `model` and `stress` modules expose `parse_definition(raw)` and `forecast(features, definition)` while keeping immutable data shapes independent from computation. The latter follows the prescribed architecture, makes the IO boundary explicit, and leaves the ledger as the sole file owner. Both need the same input values and expose the same two operations. Neither hides the unresolved choices.
