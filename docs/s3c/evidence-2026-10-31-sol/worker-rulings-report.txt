S3c is not ready for a prospective forecast. The pure model implements much of the frozen calculation, but the current path has point-in-time gaps, and `_season_window` rejects some dates that do not require a leap-day decision.

1. **P1: First-recorded timestamps can predate commit.** The history loader selects rows that are committed *now*, orders them by `loaded_at`, and uses that timestamp as availability. EIA and NCEI can first index a batch as pending and commit it later. A batch indexed before an issue time but committed afterward can therefore appear available at issue time on a later reconstruction. Replays also update `observed_at`, so it does not preserve the first commit time. See [stress_inputs.py:56](C:/Users/ajbig/Documents/grid-project/src/grid_pipeline/stress_inputs.py:56), [fetch.py:135](C:/Users/ajbig/Documents/grid-project/src/grid_pipeline/fetch.py:135), and [ncei.py:79](C:/Users/ajbig/Documents/grid-project/src/grid_pipeline/ncei.py:79).

2. **P1: A prospective forecast can be issued after its target day.** [forecast](C:/Users/ajbig/Documents/grid-project/src/grid_pipeline/stress.py:225) checks that timestamps precede `issued_at`, but not that `issued_at` precedes the start of target date D. In an in-memory reproduction, a July 1 target using historical values first available July 2 and an issue time of July 3 returned `SCORED` with `verified_at_issuance`. The architecture assigns the late-issuance refusal to a future ledger step, but that step is not present in the inspected path. [Architecture](C:/Users/ajbig/Documents/grid-project/docs/architecture-s3-s7.md:90)

3. **P1: The seasonal guard rejects unambiguous dates and raises instead of returning a no-call.** [_season_window](C:/Users/ajbig/Documents/grid-project/src/grid_pipeline/stress.py:131) raises for 85 dates in 2025 and 86 in 2028, including all windows crossing New Year. It also rejects February 7, 2026, although its ±21-day window is January 17 through February 28 in every relevant year, including 2024. Existing tests expect refusals for January 1 and a leap-day boundary but do not cover that false rejection. [Tests](C:/Users/ajbig/Documents/grid-project/tests/test_stress.py:99)

4. **P1: There is no verified NWS-to-forecast input path yet.** The only non-test forecast caller I found is the diagnostic. It supplies current mart temperatures but attaches the timestamp of the *first-recorded* temperature row, so the timestamp does not establish availability of those exact values. It is an observed-weather probe, not an issued NWS forecast reconstruction. [diagnose_s3c.py:30](C:/Users/ajbig/Documents/grid-project/scripts/diagnose_s3c.py:30)

   The cleaned NWS daily view groups nighttime lows by their **start** date, and can combine periods from different nights on that date. It cannot safely supply D’s morning low without a period-level mapping to the night’s end date. The calendar-day convention itself is settled in [S3b’s definition](C:/Users/ajbig/Documents/grid-project/docs/s3b-day-history.md:51); see also [nws_forecast_daily.sql:1](C:/Users/ajbig/Documents/grid-project/dbt/models/cleaned/nws_forecast_daily.sql:1) and [its test fixture](C:/Users/ajbig/Documents/grid-project/tests/test_nws_dbt.py:51).

5. **P2: Alert interval mapping is not connected to the forecast path.** The model accepts date-keyed annotations, and the interval helper handles half-open intervals across local dates, but I found no caller connecting NWS alert fields to that helper. The input tests import it without testing it. Thus the real path does not yet establish the “any overlap” rule or issue-time availability of displayed alerts. [stress_inputs.py:144](C:/Users/ajbig/Documents/grid-project/src/grid_pipeline/stress_inputs.py:144), [nws_alerts.sql:1](C:/Users/ajbig/Documents/grid-project/dbt/models/cleaned/nws_alerts.sql:1)

6. **P2: The near-zero hinge policy has a material boundary case.** The implementation requires both a particular relative standard-deviation cutoff and a two-column condition check before dropping a hinge. With a heat-hinge standard deviation of about `1.5e-10` and a two-column condition number of `1.33e10`, my probe retained neither hinge and used intercept-only, although the cold hinge alone fit exactly. Whether that violates the ruling depends on the intended numerical definition of “near-zero.” [stress.py:86](C:/Users/ajbig/Documents/grid-project/src/grid_pipeline/stress.py:86)

The remaining decisions I could not derive from the supplied rulings or repository definitions are how to anchor leap-day windows across leap and non-leap years, the numerical cutoff for a near-zero hinge and the matrix whose condition number is tested, and which NWS fields define an alert interval when `effective`, `onset`, `expires`, and `ends` differ or are missing. Those are the focused questions for Darren if his full rulings did not already settle them. The implementation also uses the valid analog-candidate pool to calculate z-score scales; that reference population should be made explicit in the frozen definition.
